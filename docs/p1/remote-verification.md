# 远程工具链的手动验收

当前只有 macOS ARM64 本机实测；以下是待执行步骤，**不是已经通过的结果**。

1. 在本机安装构建的 VSIX，打开 SDK/工具链页面。应显示“本机”及实际平台架构，后台发现工具链，不需要先点击扫描。关闭重开，缓存应先显示，再按有效期刷新。
2. 连接 Remote WSL/SSH/Dev Container，确认扩展安装在工作区侧。页面应分别显示 WSL/SSH/Dev Container。使用命令面板“Sakura Atelier: 打开当前环境的全局工具链注册表”核对宿主 ID、来源、验证时间。文件位于当前宿主 globalStorageUri，不在项目里。
3. 为本机和远程选择明显不同的 SDK 路径/版本。远程列表和运行进程只能对应远程文件系统；断开远程不应在本机弹出替代进程。命令面板“重新扫描当前环境的工具链”只扫描当前宿主。
4. 切换两个 SSH 主机，重复检查注册表 ID/缓存；在远程让一个手动工具路径失效后重连，记录应不可用但仍保留。容器重建后重复，不得继续相信上个容器的缓存验证时间。
5. 在远程打开普通项目和调试项目，分别验证运行、断点、变量和 Stop。只在本机安装调试器时，远程必须提示在目标宿主安装对应扩展；不能声称调试启动成功。Stop 不能停止手动启动的其他会话。
6. 打开 SDK 包详情并点击安装，在最终确认前取消：核对目标主机、系统架构、安装范围、实际命令和权限；不能启动安装任务。容器应明确“当前容器内部”。受支持的 Linux 才启用 APT。
7. 用未信任的工作区重复扫描/运行/调试/安装：允许读取缓存，禁止命令执行。
8. 有运行/安装任务时断开远程，确认宿主清理自己拥有的操作；重连重新验证缓存。不承诺网络分区时立即终止仍存活的远端进程，这受 VS Code 宿主生命周期限制。

不要为验收修改系统 PATH、Shell 启动文件、系统默认 SDK 或第三方软件源。实际安装与管理员操作仍需用户在原生确认框明确授权。

P0 合并时将 package.nls 新增的两个命令键合入其完整字典即可；不应替换 P0 字典。SDK 页面目前通过既有 sdkStatus 显示环境与扫描时间，专用徽标/按钮布局由 P0 接口集成。
